# Implementation sequence

Follow [the findings](01-findings.md) and update [the checklist](index.md) at every checkpoint. Each stage lists the old behaviour, the change, the expected result and a checkpoint. Do not start a stage before the previous stage's checkpoint is recorded.

## Stage A — signals and schema safety (A01-A03)
Old: the three new entities are declared in Kotlin but absent from the committed ObjectBox model, so ids and UIDs are regenerated per build; `ReviewSignals` is hardcoded to all-false so no review is ever enqueued; the scheduler drains the hardcoded `"default"` profile while the enqueuer writes to the active memory space.
Change: regenerate and commit `app/objectbox-models/default.json` together with the entity declarations, assigning stable ids and UIDs to `TaskEpisodeEntity`, `SkillRevisionEntity` and `PendingReviewEntity` without renumbering any existing entity; derive the four review signals from deterministic outcomes (explicit user correction, terminal tool failure, repeated repair count, complex success above a step threshold); resolve the scheduler's profile id the same way the enqueuer does and drain every memory space that has pending reviews.
Expected: the database opens after an update over an existing install with existing memories intact; a correction or failure turn enqueues exactly one review; a review enqueued in a non-default memory space is drained in that same space.
Checkpoint: the committed model file with the three new entity ids and UIDs, the signal-to-event mapping, a test per signal, and a CI run URL. Do not mark A01 verified before the update-over-existing-install check has actually run.

## Stage B — scheduler robustness (B01-B02)
Old: `drainPendingReviews` deletes the whole batch when any one review succeeds; failed reviews retry forever with no attempt cap; rows left in `PROCESSING` after a crash are never re-queried; `useEnglish` is hardcoded true.
Change: delete only the ids that succeeded; add an attempt cap with a terminal dead-letter status; add a startup sweep that returns stale `PROCESSING` rows to `PENDING`; derive `useEnglish` from the user's locale as `ConversationService` already does.
Expected: no review is lost or retried without bound; a crash mid-batch does not strand rows; Chinese-locale users receive Chinese lessons.
Checkpoint: a partial-failure batch test, an attempt-cap test, a crash-recovery test, a locale test, and the commit.

## Stage C — retrieval and gap check (C01-C06)
Old: `workspacePath` is passed as `currentTaskContext`; prerequisite matching accepts any single shared token with no stopword list; `missingPrerequisites` is never called in production; tokenization is Latin-only; retrieval is a full-table scan that ignores the vector index and the `MemoryLink` graph; the episode schema has no signature, omissions, structured conditions or warning feedback.
Change: pass the real task description as context; add a stopword list and a match threshold; call `missingPrerequisites` from the production preflight path; tokenize with a Unicode-aware splitter; use the vector index for candidate generation and the graph for bounded expansion; add `taskSignature`, `omittedFromRequest`, `applicabilityConditions`, `trajectoryRef`, `warningsHelpful` and `warningsDismissed` as a compatible metadata extension; extend both Reflector prompts to emit `omitted_from_request` and `applicability_conditions` and extend `parseEpisode` to read them; add the plan-time gap check that retrieves 3-5 episodes, tests conditions, emits at most three caution-phrased warnings, records accept/dismiss and retires repeatedly dismissed lessons, attached to the existing planning call.
Expected: Chinese tasks retrieve relevant episodes; a fresh-install task does not match an update-only prerequisite even when the sentences share common tokens; a request that omits a prerequisite that mattered before produces at most three cautions and never a new user mandate; no unconditional extra model call per turn.
Checkpoint: the update-versus-fresh-install distinction demonstrated with deliberately overlapping sentences, a Chinese retrieval test, a bounded-query assertion, a warning-precision test, and the commit.

## Stage D — skill lifecycle and governance (D01-D07)
Old: `ReflectorCurator.curate`, `SkillRevisionLifecycle` and `SkillRevisionRepository` have no production callers; a `CORRECTS`/`SUPERSEDES` link retires its target permanently on an LLM-extracted, title-matched link with no confirmation and no reactivation; `MIN_INDEPENDENT_EVIDENCE` is 1, helpful outcomes are not required, paraphrases count as independent evidence, and constraint preservation trusts the candidate's self-report; reinforcement fires on raw text inequality, salience metadata is loaded per memory, and a flat propagation floor is added to every edge; architect rules are injected into every workspace task in every project with prompt-only enforcement; episodes are injected into system prompts without provenance or sanitization; list fields are newline-joined and lossy.
Change: wire the Curator and the revision lifecycle into the post-review path, or record them as library-only with a visible note under T07-T10 in the existing index.md without deleting history; add a governance gate that verifies link direction and recency, checks active user constraints and makes retirement reversible; raise the evidence threshold, require a helpful outcome, collapse paraphrases by similarity and check candidate steps rather than self-reported constraints; reinforce only on semantic novelty, batch the salience query and drop the unconditional propagation floor; scope architect rules per project and either enforce the build restriction at dispatch or document the gap; add provenance, sanitization and a whole-block length cap to injected episodes; encode list fields losslessly.
Expected: a reversed or hallucinated link cannot retire the correct fact and any retirement can be undone; a single incident cannot promote a revision; a whitespace-only edit does not count as novelty; an unrelated project receives no HandleIT rules; an episode containing instruction-like text cannot alter behaviour.
Checkpoint: a reversed-link test, a reactivation test, a paraphrase-dedup test, a step-violation test, a query-count assertion, a cross-project scoping test, a prompt-injection test, a newline round-trip test, and the commit.

## Stage E — trajectory log for future local-model migration (E01-E02)
Old: no raw trajectory record exists; episode summaries are lossy by design; retrieval uses only distilled summaries.
Change: add an append-only JSONL trajectory log separate from episode summaries, carrying a schema version, model id, system prompt version, playbook and skill versions, ids of retrieved episodes and skills, the prompt context, tool calls and results, the final response, an outcome label and correction pairs; redact secrets at write time, cap and rotate on device, exclude sensitive chats by default and record the embedding model name. Make raw trajectories the primary retrieval source and distilled skills a supplement, gated to hard or pattern-matching tasks.
Expected: one well-formed record per completed turn with no secrets; the log rotates at its cap; an excluded chat produces no record; a hard task retrieves trajectories ahead of skills.
Checkpoint: a record-shape test, a secret-redaction test, a rotation test, an exclusion test, a retrieval-priority test, and the commit. Before any training use, check the provider terms for training on another provider's outputs and record the conclusion.

## Stage F — evaluation (F01-F02)
Old: no replay fixtures and no lesson A/B comparison exist; teacher-comparison evaluation was never measured.
Change: build replay fixtures from real tasks and compare baseline, with-lesson and without-lesson runs before promoting a lesson; tune retrieval weights and thresholds against the replays with automatic revert on regression.
Expected: a lesson is promoted only after a replay shows it does not regress the baseline; a regression automatically reverts the tuned weights.
Checkpoint: the fixture set, the measured comparison table, the revert mechanism, and the commit. Record only measured numbers; leave unmeasured comparisons marked pending.
