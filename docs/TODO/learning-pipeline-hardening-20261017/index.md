# Learning pipeline hardening

## Plain-English reason
The learning pipeline that was built in `docs/TODO/reliable-learning-architect-20261016/` is mostly present as code but is not actually running: the review queue is never filled, the scheduler drains the wrong memory space, the Curator and the skill-revision lifecycle have no production callers, and retrieval ignores the vector index and the graph. This checklist records an independent static review of that pipeline as an ordered, checkable TODO so later jobs can fix it in sequence. Every finding below was re-verified against the code at commit `28b53abd` before being recorded; findings that were already fixed or wrong at HEAD are marked as such in [01-findings.md](01-findings.md) instead of being copied forward.

## Progress rules
Read this file on task start, resume, and after context compaction. Keep a current checkpoint with owner/job, exact commit, next action, and blockers. Update after each meaningful verified milestone, not only at the end. Check an item only with commit and verification evidence. Distinguish implemented, CI-verified, and device-verified. Pending or blocked items remain unchecked. Never mark the entire job complete merely because a build passes. This job is documentation only: it records findings and a plan, it does not implement them.

### What was repaired
- **D07 / `StringListCodec`**: replaced the first-`}` shape guess with a JSON-aware structural discriminator plus strict parsing. A `}` inside a string item no longer misroutes a valid envelope to Legacy, so `encode(listOf("a {b} c", "}", "{\"nested\":1}"))` round-trips and repeat migration is idempotent. Truncated/malformed versioned data and trailing junk surface as Corrupt; unknown versions as UnsupportedVersion; never Legacy and never silently empty. Legacy newline decoding is preserved exactly. The compatibility policy is documented honestly: the discriminator is structural, not a magic prefix, so a legacy row whose entire content is a single JSON object with a `v` field is indistinguishable and is surfaced (Corrupt/UnsupportedVersion) and left untouched with NEEDS_ATTENTION rather than guessed at.
- **Shared observation store**: `EnhancedAIService` and `ConversationService` now share one `ObservationCoordinator` (created by `EnhancedAIService`, injected into `ConversationService`), so the store tool results are WRITTEN to is the store preflight READS from. The memory space is resolved identically on both sides via `ObservationScopeResolver`. The session generation is stamped as the `sessionId` coordinate and rotated on chat-instance release and execution invalidation; a late tool result from an old generation is rejected. `projectScope`/`executorId`/`environment` remain unknown (`""`) on both sides and are documented as a limitation; the snapshot is advisory and does not gate execution.
- **Deterministic TTL**: `TaskContextSnapshotStore` now enforces a bounded default TTL from the injected clock, honors an earlier explicit expiry, fails closed for future observation times / clock rollback, clamps overflow, and uses an explicit expiry boundary (`now >= validUntilMs`). `ToolObservationProducer` accepts an optional explicit expiry; `0` means the store applies the default bound.
- **Migration atomicity**: `TaskEpisodeRepository` and `SkillRevisionRepository` now plan the whole row first (`RowMigrationPlanner`) and mutate/persist only eligible rows; a row with any corrupt/unsupported field is left entirely untouched in memory and on disk.

### Known limitations (honest)

- Ambiguous legacy-vs-envelope strings cannot be universally disambiguated without a persistent discriminator (which would require a schema change forbidden here); such rows are retained with a needs-attention outcome.
- ObjectBox migration-on-device and upgrade testing cannot be performed from CI; A01 remains PARTIAL. Nothing in this repair is device-verified.

## Step 1 codec & data integrity repair (follow-up to bridge #36)

This is a bounded repair of the Step 1 codec and data-integrity work after the independent review of bridge #36 did NOT establish Step 1 acceptance. It is NOT Stage 2 (the next stage is D06 safe memory rendering and G02 execution-route audit). No Job 2 observation-lifecycle changes, no Stage 2 D06/G02 rollout, no graph/relational entities, no H01, no vector caching, no orchestrator redesign. The scoped plan is [05-step1-codec-integrity-repair-plan.md](05-step1-codec-integrity-repair-plan.md).

Base: `f495c1083b204ee1c50eb333600a68c3a32c963d` (code SHA `41c9968fe173a334d24a7fefb827f4266557565d`). Repair branch `fix/step1-codec-integrity`.

### What was repaired
- **A. Codec provenance (`StringListCodec`)**: added an explicit fifth decode outcome `Ambiguous` for brace-starting bytes whose provenance (legacy literal vs versioned envelope) cannot be proven. The Corrupt-vs-Ambiguous split is decided by a parse-independent prefix test (`looksLikeEnvelopePrefix`: `{` + optional whitespace + `"v"` + optional whitespace + `:`), NOT by a lenient re-parse. Truncated, trailing-junk, wrong-item-type, extra-key, non-integer-`v` and missing-`items` payloads that start with the envelope prefix are `Corrupt`; brace-starting text that is not envelope-shaped (e.g. `{"a":1}`, `{placeholder}\nsecond_item`) is `Ambiguous` and preserved verbatim. Unknown `v` is `UnsupportedVersion`. Non-brace-starting values keep the exact legacy newline semantics. The unprefixed `{"v":1,"items":[...]}` envelope format is unchanged (the f39e4358 build already wrote it; a prefix would strand those rows). `StringListMigration.migrateValue` maps `Ambiguous` to `NEEDS_ATTENTION` and never rewrites it. Honest limitation: strict JSON proves syntax, not historical intent; a newline does not prove legacy; brace-starting legacy text is preserved as Ambiguous rather than guessed.
- **B. Non-persisted integrity metadata (`ListFieldIntegrity` / `RowListIntegrity`)**: `TaskEpisode` and `SkillRevision` now carry a non-persisted `listIntegrity: RowListIntegrity` (default `HEALTHY`) that distinguishes a genuine empty list from an unresolved field (CORRUPT / UNSUPPORTED_VERSION / AMBIGUOUS), retaining the field name, reason/version and the original raw stored string for controlled recovery. Raw stored bytes are never rendered into prompts or logs. `RowListIntegrity` equality is defined over the unresolved fields only, so an all-healthy row equals `HEALTHY` whether its map is empty or populated.
- **C. Fail closed in real consumers**: `TaskEpisodeRetrieval.episodeApplicability` returns a machine-readable `EpisodeApplicability.INELIGIBLE_UNRESOLVED_INTEGRITY` when `requiredPrerequisites` or `applicableConstraints` is unresolved, and `TaskPreflightFormatter.buildPreflightBlock` consumes it to emit a bounded FIXED caution (no raw payload, no field-name interpolation, no duplicated memory block). `SkillRevisionLifecycle.evaluate` rejects a candidate with ANY unresolved list field (`passed=false`, explicit reason) before any constraint/evidence logic; `preservesUserConstraints` returns false for an unresolved candidate; a baseline-aware `evaluate(candidate, authoritativeRevision, ...)` overload rejects an unresolved authoritative revision so unresolved constraints cannot be bypassed. This is memory applicability integrity, NOT a universal execution security gate; no G02 claim.
- **D. Write preservation**: `TaskEpisodeEntity.fromEpisode` / `SkillRevisionEntity.fromRevision` preserve the original raw bytes of any unresolved field verbatim from the captured `ListFieldIntegrity.rawStored`, unconditionally — there is no caller-supplied `originalRaw` map and no DB read. `save(...)` is a single `put()`; the previous read-then-put TOCTOU is eliminated. `resavePreservingUnresolved` and `UnresolvedWriteGuard` were removed because preservation is now unconditional at the entity boundary. (No production read->save round-trip exists today; the only production writer, `ReviewScheduler`, saves a freshly-constructed healthy episode, so the risk was theoretical, but the invariant now lives in the entity write path and cannot be bypassed by a caller.)
- **E. Whole-row migration**: `RowMigrationPlanner` (unchanged logic) treats `Ambiguous` as `NEEDS_ATTENTION`; any NEEDS_ATTENTION row is left entirely untouched in memory and on disk; repeated migration is idempotent; the corrupt-later-field case is covered.

### Known limitations (honest)
- Universal legacy-vs-envelope discrimination cannot be fulfilled under the fixed schema without a persistent discriminator (forbidden here). Brace-starting legacy text is preserved as `Ambiguous` and surfaced, not silently decoded or rewritten. This is NOT a claim that unresolved compatibility is fully complete.
- Envelope-shaped legacy literal collision is a documented **PARTIAL / BLOCKED** limitation, not resolved: a pre-Step1 legacy value that is itself a well-formed envelope-shaped JSON object is byte-indistinguishable from a real versioned envelope and decodes as `Versioned`/HEALTHY. See the `StringListCodec` KDoc; the durable fix is a schema change and is out of scope.
- JVM/source evidence only. ObjectBox migration-on-device and upgrade behavior cannot be performed from CI; A01 remains PARTIAL. Nothing in this repair is device-verified.

### Known behavior and follow-ups

- **Unresolved episodes still occupy retrieval topK slots.** Episodes with unresolved list fields are still returned by retrieval and render a fixed caution line; consider excluding or down-ranking them in the retrieval ranking.
- **Evidence counting is not gated by `episodeApplicability`.** `TaskEpisodeRetrieval.countIndependentEvidence` (which deduplicates `evidenceKeys` across episodes via `deduplicateEvidenceKeys`) does not consult `episodeApplicability`; an unresolved `evidenceKeys` field decodes to an empty list and therefore counts as zero evidence. This deliberately contributes zero evidence and makes promotion harder; no applicability gate is added to evidence counting.
- **Recovery-byte diagnostics are redacted.** `ListFieldIntegrity.toString()` and the unresolved `DecodedList` variants replace `rawStored` / `stored` with `<redacted>`. Nested domain-object diagnostics inherit this redaction; raw properties remain available for preservation. This is not blanket sanitization of ordinary task text or all storage objects.
- **`fromEpisode` / `fromRevision` silently ignore caller edits to an unresolved field.** They write the captured raw bytes back and discard caller-supplied values for that field; an explicit resolution path does not exist yet.
- **Envelope-shaped legacy literal collision remains PARTIAL / BLOCKED** pending a durable per-field discriminator (a schema change, out of scope here).
